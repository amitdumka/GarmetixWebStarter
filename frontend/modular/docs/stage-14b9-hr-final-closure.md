# Stage 14B.9 HR Final Closure

Version: `6.0.17`

This stage closes the HR modular parity lane at code-readiness level and makes the remaining production handover gates explicit.

## Added

- `hr-final-closure.mjs` verifies HR parity artifacts across:
  - attendance today/monthly review,
  - manual punch and regularization,
  - guarded monthly actions,
  - device and kiosk readiness,
  - payroll review,
  - salary draft and payslip generation guard,
  - salary payment generation guard,
  - payroll report/export evidence.
- Root and modular package scripts now expose:

```powershell
npm.cmd run modular:hr:final-closure
npm.cmd --prefix frontend\modular run hr:final-closure
```

## Closure Status

Default status is `CONDITIONAL` when no live HR token/manual acceptance flags are supplied.

Production handover can be made strict with:

```powershell
$env:GARMETIX_SMOKE_AUTH_TOKEN='<hr capable token>'
$env:GARMETIX_HR_MANUAL_ACCEPTANCE='YES'
npm.cmd run modular:hr:final-closure -- --require-token --require-manual
```

## Safety

- No attendance rows are created or deleted by the closure gate.
- No payslips are generated by the closure gate.
- No salary payments or accounting vouchers are generated by the closure gate.
- No database schema change is included.
