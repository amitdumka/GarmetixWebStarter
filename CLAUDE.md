## 2026-07-10 - Stage 14Q.5: Security fix - factory reset is now genuinely SuperAdmin-only

Amit asked to fix the long-flagged factory-reset authorization bug (open since the very first 2026-07-07 analysis pass) right after I re-surfaced it in a "what's left" summary. Version `6.2.4`. Backend-only change, no schema/DB impact.

- Root cause was structural, not a simple typo: `POST /api/factory-reset` was route-gated with `RequireAuthorization(GarmetixPolicies.Admin)`, but `AccessPermissionMatrix.CanAccessPolicy` grants a blanket pass to `IsAdminOrOwner(user)` (SuperAdmin, Admin, *and* Owner) **before** evaluating any policy name - so every policy registered through the shared `AddMatrixPolicy` mechanism, including `Admin`, is really "Admin-or-above," and none of them can express "SuperAdmin only."
